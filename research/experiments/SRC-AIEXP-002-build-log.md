## 事例1 数値と人名の誤り

### 何をさせたか

agy に「文書の書き方がAIの正答率に与える影響を実測した研究」を集めさせた。指示には次を入れた。

- 数値は数値のまま記録する。「大きく低下した」ではなく「87%から62%に低下した」と書く。
- 査読つきか、査読前か、企業のブログかを明記する。
- 推測した部分には「【推測】」と付ける。

### 返ってきたもの

27,172バイトの詳細な報告である。論文名、著者、arXiv番号、測定条件、数値が並んでいた。**見た目には非常に良い報告だった。**

### 私が原文で確認した結果

| 項目 | agy の報告 | arXiv の原文 | 判定 |
|---|---|---|---|
| NoLiMa の存在と主旨 | あり | あり | **正しい** |
| NoLiMa の「32Kで11モデルが基準の50%未満」 | あり | 要旨に同じ記述あり | **正しい** |
| NoLiMa の著者 | Hosein Deilamsalehy | **Hanieh** Deilamsalehy | **誤り** |
| NoLiMa の著者 | Tung Bui | **Trung** Bui | **誤り** |
| Lost in the Middle の存在と主旨 | あり | あり | **正しい** |
| Dense X Retrieval の「Recall@5 が17〜25%向上」 | あり | **要旨に数値の記載なし** | **確認できず** |
| Shi et al. の「Macro Accuracy が30%未満」 | あり | **要旨に数値の記載なし** | **確認できず** |
| 分割方法の比較（arXiv 2603.06976） | nDCG@5 0.244未満 対 約0.459 | 要旨に同じ記述あり | **正しい** |

### 分かったこと

**論文の存在と中心の主張は正しかった。誤ったのは細部である。**

1. **人名の転記が2件間違っていた。** 音は近いが綴りが違う。
2. **要旨に無い数値が2件付いていた。** 本文にある可能性はあるが、確認できない。

**「だいたい合っている報告」が最も危ない。** 全部でたらめなら気づく。論文名も主張も正しく、数値だけが違うと気づかない。

→ 規則 `AV-02`（数値と固有名詞は、必ず原文に当たる）の根拠である。

## 事例2 二次情報のほうが誤っていた

### 何が起きたか

私（Claude）がWeb検索したところ、上位の解説記事に次の記述があった。

> Claude Code also reads AGENTS.md as a fallback if no CLAUDE.md is found in a directory.

同じ対象を調べさせた agy の報告は、これを否定した。

> Claude Code は CLAUDE.md を明示的に読み込み、AGENTS.md は読み込みません。

### 決着

公式文書に当たった。

> "Claude Code reads `CLAUDE.md`, not `AGENTS.md`."

**agy が正しく、二次情報が誤っていた。**

### 分かったこと

**「AIは間違える」でも「AIは正しい」でもない。** 一次情報に当たるまで決まらない。

補助AIを疑うのと同じだけ、Web検索の上位に出る記事も疑う必要がある。

→ 規則 `AV-03`（「無い」ことをAIに確認させない）と `AV-05`（独立した別のAIに調べさせる）の根拠である。

## 事例3 指示した通りに「取得できなかった」と書いた

### 何が起きたか

指示に「ページが開けなかった場合は『取得できなかった』と正直に書く。推測で埋めない」を入れた。

agy の報告には、実際に次の記述が含まれた。

> `https://docs.anthropic.com/en/docs/agents-and-tools/claude-code/memory` への直接アクセスは **404 エラー（取得できなかった）** となりましたが、公式ポータルおよび公開ドキュメントインデックスから仕様を確認しました。

### 分かったこと

**「書けなかったことを書け」と指示すると、実際に書かれる。** 指示しなければ、その部分は推測で埋められていた可能性がある。

→ 規則 `AV-01`（主張ごとに出典を書かせる）の根拠である。

## 事例4 補助AIが作業を完了できなかった

### 何が起きたか

codex に、書籍3冊の抽出テキスト（97万〜157万バイト）から一次ノートを作らせた。

**45分経っても1件も完了しなかった。** 途中経過も出なかった。

### どうしたか

**codex の作業を止め、私（Claude）が原文を読んでノートを作った。** そのことを各ノートの冒頭に明記している。

```markdown
> **この文書の出どころ**: Claude（Opus 5）が抽出テキストを読んで作成した一次ノートである。
> **本書の全体を読んだものではない。**
```

**読んだ範囲と読んでいない範囲を、各ノートの末尾に書いた。**

### 分かったこと

**補助AIが完了しないことは起こる。** そのとき、次のどちらかを選ぶ。

1. 自分でやる。**やったことと、やっていないことを明記する。**
2. できなかったと書いて、その材料を使わない。

**やっていないのに「やった」と書かない。** この別冊の書籍3冊のノートは、全体ではなく一部しか読んでいない。**そのことを各ノートに書いてある。**

## 事例5 補助AIの権限設定でつまずいた

### 何が起きたか

agy を非対話で動かしたところ、URLの読み取りが自動で拒否された。

```text
jetski: no output produced — a tool required the "read_url" permission that
headless mode cannot prompt for, so it was auto-denied.
```

### どうしたか

`--dangerously-skip-permissions`（すべての道具を自動承認する）は使わなかった。**代わりに、調べさせる対象のドメインだけを許可一覧に足した。**

このリポジトリの前回の調査でも、同じ形で `read_url(https://diataxis.fr)` などが足されていた。**その形に合わせた。**

### 分かったこと

**補助AIに広い権限を与えて解決しない。** 必要な範囲だけを開ける。読み取りだけの許可なら、取り消しも容易である。

→ この別冊の規則ではなく、**補助AIの使い方についての記録である。**
