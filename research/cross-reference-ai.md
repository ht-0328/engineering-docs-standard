# 原則 × 出典 の突き合わせ（AI向けの別冊）

## この文書の目的

**[docs-ai/](../docs-ai/index.md) の各規則が、どれだけ多くの独立した出典に支持されているかを示す。**

本編の [cross-reference.md](cross-reference.md) と同じ役割である。私（Claude）の意見だけで規則を作らないための歯止めである。

## 判定の基準

本編と同じ基準を使う。

| 支持の強さ | 判定 | 標準での扱い |
|---|---|---|
| 独立した3出典以上が直接支持 | **中核** | 規則にする |
| 1〜2出典 | **補助** | 規則にしてよい。ただし出典欄からその薄さが読み取れるようにする |
| 出典間で対立 | **要判断** | 両論と、どちらを採るかの条件を書く |

**規範度（必須・推奨・任意）は、ここでは決まらない。** 出典数は「どれだけ確からしいか」、規範度は「守らないとどれだけ実害が出るか」を表す。単一出典でも実害が大きければ必須にする。

## AI向けの別冊で足した基準

本編に無い事情が2つあるため、数え方を2つ足した。

### 足した基準1 ベンダー文書は、合わせて2出典分までとする

Anthropic、OpenAI、Google、kapa.ai などの文書は、互いに引用していなくても**同じ利害を持つ。** 「自社の製品をこう使うと良い」という立場である。

そのため、**ベンダー文書は何件集まっても、合わせて2出典分までとして数える。**

3出典目には、次のいずれかが要る。

- 査読を経た研究。
- 単一ベンダーのものでない公開仕様。
- 書籍。
- **自分で測った結果。**

**この基準は本編に無い。この別冊が決めたものである。**

### どれをベンダー文書として数えるか

**数え直せるように、区分を明示する。**

| ID | 区分 | ベンダーか |
|---|---|---|
| X2、X3、X7 | Anthropic の製品文書 | **ベンダー** |
| X6 | kapa.ai の指針 | **ベンダー** |
| X9 | MCP 仕様（非ベンダー）と OpenAI ガイド（ベンダー）の混合 | **どちらの支持かを行ごとに `X9(MCP)` `X9(OpenAI)` と書き分ける。** 両方が支持する場合も1出典分として数える |
| X5 | Chroma の技術レポート | **ベンダーとして数えない。** 測定条件と生データを公開しているため |
| **W1、W2、W3**、X1、X4、X8、P1、P2 | 書籍・個人の提案・公開仕様・査読つき研究・自分の実測 | ベンダーでない |

**X5 の扱いは判断である。** Chroma は企業であり利害を持つ。それでも数えるのは、**主張ではなく測定結果を引いているため**である。この判断に納得できない場合、X5 を外して数え直せる。外しても A5・A6・A7 は中核のまま残る。

### 足した基準2 自分で測った結果を出典として数える

この分野は測れる。測ったものは `SRC-AIEXP-xxx` として出典に加える。

**測定の条件と生の結果を公開したものだけを出典にする。** 手順は [docs-ai/appendix-experiments.md](../docs-ai/appendix-experiments.md) にある。

### 数え直して中核から外したもの

**A9（説明文に「何をするか」と「いつ使うか」を書く）は、中核の基準を満たしていなかった。**

最初は「W2（書籍）、X3（Anthropic）、X9（OpenAI）の3出典が支持する」と数えていた。数え直して2つの誤りが分かった。

| 誤り | 内容 |
|---|---|
| 1 | **W2（書籍）はこの原則を述べていない。** 述べているのは「明快で他のツールと混同されない説明を書く」であり、**「いつ使うか」を書けとは言っていない。** ● ではなく ○ である |
| 2 | **X9 のうち OpenAI はベンダー文書である。** ベンダー以外として数えていた |

正しく数え直すと次になる。

| 区分 | 出典 | 数 |
|---|---|---|
| ベンダー以外の直接支持 | なし | **0** |
| ベンダー文書 | X3（Anthropic）、X9 のうち OpenAI | 2出典分まで |
| **実質** | | **2** |

**したがって A9 は補助である。** 対応する規則 `AK-01` は、**規範度としては必須のまま**にしている。理由は下の補助の表に書いた。

**規則にはするが、根拠が薄いことを各規則に明記する。**

|---|---|---|---|---|---|

| B2 | 矛盾を残さない | X7 | **1** | `AN-06` | **必須** |
| B3 | 指示書に強制力は無い。必ず守らせたいことは仕組みで行う | X7 | **1** | `AN-11` | **必須** |
| B4 | 図だけに情報を持たせない | X6 | **1** | `AD-09` `AH-02` | **必須** |

| B8 | 数値と固有名詞は原文に当たる | P2 | **1** | `AV-02` | **必須** |

| B13 | 指示書を人向けREADMEと分ける | X4 | **1** | `AN-01` | 必須 |
| B14 | 説明文に「何をするか」と「いつ使うか」を書く | X3、X9(OpenAI)。**どちらもベンダー** | **2** | `AK-01` | **必須** |

### 単一出典でも必須にしたもの

**B2、B3、B4、B6、B8、B13 は出典が1件しかないが必須にしている。B14 は2件だが、どちらもベンダー文書である。** 理由は次である。

| # | 必須にした理由 |
|---|---|
| B2 矛盾 | 矛盾は誤りとして報告されない。**気づけないまま誤った結果が出る** |
| B3 強制力 | これを誤解すると、守られない前提で仕組みを作らない。**事故が起きる** |
| B4 図 | 図だけに情報があると、AIはその情報を持たない。**答えが欠ける** |
| B6 時点 | AIは書かれた時点を知らない。**古い記述を現在の事実として使う** |
| B8 原文確認 | 実際に誤りが出た。**数値の誤りは規則の根拠を壊す** |
| B13 分離 | 出典は1件だが、その1件は**複数社が協働して作った公開仕様**である |
| B14 説明文 | 根拠はベンダー文書だけである。**しかし、これを守らないと道具が呼ばれない。** 仕組みから直接導かれる要求であり、実害が大きい |

**出典数と規範度は別の軸である。** この判断は本編の考え方をそのまま引き継いでいる。

## 出典が対立している箇所

**両論と、どちらを採るかの条件を規則に書く。**

### 対立1 「いつ使うか」をどこに書くか

| 出典 | 立場 |
|---|---|
| X3（Anthropic） | 説明文の中に書く |
| X9（OpenAI） | システムプロンプトに書く |

**この別冊の扱い**: どちらも正しい。**その説明文が選択のときに読まれるかで決める。** `AK-01` に書いた。

### 対立2 例（few-shot）を入れるか

| 出典 | 立場 |
|---|---|
| X3（Anthropic） | 入れる。例は説明より明確に伝わる |
| W1 | 入れる。文書に溶け込ませる方法が「非常に効果的」 |
| X9（OpenAI） | 入れてよい。**ただし推論するモデルでは性能を損なうことがある** |

**どの出典も測定結果を示していない。**

**この別冊の扱い**: 使うモデルで試して決める。[04章](../docs-ai/04-skills-and-agents.md) の末尾に書いた。

### 対立3 構造を整えることは、常に良いか

| 出典 | 立場 |
|---|---|
| X6、X8、W3 | 構造に沿って分けると精度が上がる |
| X5 | **順序をばらばらにした文章のほうが、取り出しの成績が良かった**（18モデルすべて） |

**この別冊の扱い**: X5 が測ったのは「長い文章から1文を取り出す」課題だけである。**構造は取り出しやすさに効くが、取り出したあとの正しさを保証しない**、という限定つきで扱う。[01章](../docs-ai/01-how-ai-reads.md) の末尾に書いた。
