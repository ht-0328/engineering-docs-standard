## 要求と応答の例

> 実際に送受信できる例を書く。機密情報には架空の値を使う。

**要求例**

（例: 注文を1件作成する要求である。）

```http
POST /v1/orders HTTP/1.1
Host: api.example.com
Authorization: Bearer example-token
Content-Type: application/json

{
  "customer_id": "cus_12345",
  "amount": 1200,
  "currency": "JPY"
}
```

**応答例**

（例: 注文が作成された場合の応答である。）

```http
HTTP/1.1 201 Created
Content-Type: application/json
Location: /v1/orders/ord_67890

{
  "order_id": "ord_67890",
  "status": "created",
  "amount": 1200,
  "currency": "JPY"
}
```

## エラー一覧

> 状態コードごとの発生条件を書く。呼び出し側が取る行動も示す。

| 状態コード | エラーコード | 発生条件 | 呼び出し側の行動 |
|---|---|---|---|
| `400` | `INVALID_REQUEST` | （例: 必須フィールドが欠けている） | （例: 要求内容を修正して再送する） |
| `401` | `UNAUTHORIZED` | （例: トークンが無効である） | （例: トークンを再取得する） |
| `404` | `ORDER_NOT_FOUND` | （例: 注文IDが存在しない） | （例: 注文IDを確認する） |
| `409` | `ORDER_CONFLICT` | （例: 同じ注文が登録済みである） | （例: 既存の注文を取得する） |
| `429` | `RATE_LIMITED` | （例: 送信回数が上限を超えた） | （例: `Retry-After` の秒数だけ待つ） |
| `500` | `INTERNAL_ERROR` | （例: サーバー内部で処理に失敗した） | （例: 要求IDを記録して再送する） |

## 制限

> レートとデータサイズの上限を書く。上限を超えた場合の応答も示す。

| 制限 | 上限 | 超過時の応答 |
|---|---|---|
| レート | （例: 1トークンにつき1分間100要求） | （例: HTTP 429を返す） |
| 要求ボディ | （例: 1MB） | （例: HTTP 413を返す） |
