# チェックリスト（1枚）

印刷して手元に置く用の1枚である。各項目の理由は本文にある。

---

## 書き始める前（[02-before-writing.md](02-before-writing.md)）

**読者と目的**

- [ ] 主たる読者を1つに決めた
- [ ] 読者の前提知識と、読む状況を書き出した
- [ ] 「読んだあと読者は〇〇ができる」を一文で書ける
- [ ] 文書の型を決めた（Tutorial / How-to / Reference / Explanation）

**範囲と運用**

- [ ] 扱わないことと、その行き先を書いた
- [ ] 保守責任者と最終確認日を決めた
- [ ] 機密区分を決め、載せてはいけない情報を確認した
- [ ] 第2階層のポイントを3〜4つに絞った

**1つでも答えられないなら、書き始めない。**

---

## 書いたあと・レビュー前（推敲）

`SRC-WRITE-003` 2.8 の方法である。

- [ ] 仕上がりより3割程度多めに書いてから削った
- [ ] 最低2回見直した
- [ ] 1日置いてから2回目を見た
- [ ] 情報の漏れがない
- [ ] 文と文のつながりが読める
- [ ] 接続詞が効果的に使われている
- [ ] 件名やタイトルとずれていない

---

## レビュー（[06-review.md](06-review.md)）

**大きい単位から小さい単位へ見る。表記から始めない。**

### 1. 内容

- [ ] 主たる読者が1つに決まっている
- [ ] 読後の行動が一文で書かれている
- [ ] タイトルから目的が伝わる
- [ ] 必要な情報が盛り込まれている
- [ ] 不要な情報が書かれていない
- [ ] 事実と意見（推定）が区別されている
- [ ] 扱わないことが書かれている

### 2. 構造

- [ ] 結論が先に書かれている
- [ ] 見出しだけを読んで筋が通る
- [ ] 見出しから中身が予測できる
- [ ] 情報の型（手順・説明・事実・注意）が混ざっていない
- [ ] 条件が指示の前に置かれている
- [ ] 一度に示す項目が絞られている（ポイント3つ / 箇条書き7項目 / 手順10ステップ）

### 3. 表現

- [ ] 一文に主題が1つ
- [ ] 動作主が明示されている
- [ ] 曖昧語が数値・固有名詞・日時に置き換わっている
- [ ] 二重否定がない
- [ ] 読者が知らない語が定義されている

### 4. 見せ方

- [ ] 色や記号だけで意味を示していないか（P-09）
- [ ] 画像に代替テキストがあるか
- [ ] コード例に前提と期待出力があるか
- [ ] 認証情報・本番データ・個人情報が載っていないか（B-07）

### 5. 表記（`doc_lint` に任せる）

- [ ] 用語が統一されている
- [ ] 文体が統一されている
- [ ] 見出しの階層が飛んでいない
- [ ] 固有名詞が正しい
- [ ] 誤字脱字がない

## 指摘を書くとき

**型**

> 〈品質軸〉現状の記述。読者への影響。直す方向。

**守ること**

- [ ] 品質6軸のどれに当たるかを言った（有用性 / 発見容易性 / 正確性 / 明確性 / 一貫性 / 保守性）
- [ ] **理由を書いた**（なぜ伝わらないのか）
- [ ] **書き換え案は書かず、方向だけ示した**
- [ ] 重大度を付けた（Blocker / Major / Minor / Note）
- [ ] 良い点も書いた
- [ ] 規約に無いことは「これは私の好みです」と明示した

## 数値の目安（合否の基準ではない）

| 対象 | 目安 | 出典 |
|---|---|---|
| 一文 | 50字 | `SRC-WRITE-003` |
| 段落 | 3〜5文、7文超えない | `SRC-EXT-001` |
| 箇条書き | 7項目以内 | `SRC-WRITE-003` |
| 説明のポイント | 3つまで | `SRC-WRITE-001` |
| 見出しの階層 | 3階層程度 | `SRC-WRITE-003` |
| 手順 | 10ステップ以内 | `SRC-WRITE-003` |
| 表のセル | 2文まで | `SRC-EXT-001` |
| 図のノード | 10まで | `SRC-WRITE-002` |

**超えたことは違反ではない。「主題が複数入っていないか」を見直す合図である。**
