# ADR-001 図の作り方を3方式の使い分けに決める

| 項目 | 内容 |
|---|---|
| 状態 | 採用 |
| 決定日 | 2026-08-28 |
| 決定者 | このリポジトリの保守担当 |
| 関連 | [05-presentation.md](../05-presentation.md) P-03 |

## 状況

この標準のサイトに図を載せる。図の作り方には少なくとも3つの選択肢がある。

1. **Mermaid** — Markdown のフェンスにテキストで書く。閲覧時に描画される。
2. **draw.io** — `.drawio`（XML）を正本にし、SVG に書き出す。
3. **手書きSVG** — SVG を直接書く。

どれか1つに決めるよう求められたが、実際に同じ図を3方式で作って測ったところ、**3つは競合していない。得意な領域が違う。**

この決定を記録するのは、あとから「なぜ図の形式が3つあるのか」と問われるためである。

## 測定

「文書の品質を測る6つの軸」という同じ図を、3方式で作って比較した。

| 方式 | 正本のサイズ | 書き出したSVG | 倍率 |
|---|---:|---:|---:|
| Mermaid | 471 バイト | 書き出し不要 | — |
| draw.io | 3,618 バイト | **176,655 バイト** | 約 42 倍 |
| 手書きSVG | 4,224 バイト | 4,224 バイト（複製のみ） | 1 倍 |

draw.io の出力が大きい理由ははっきりしている。**書体を7個、base64 で埋め込んでいる。** 166,232 文字が書体のデータであり、図そのものは 1 万文字ほどしかない。

### 明暗テーマへの追従

| 方式 | `prefers-color-scheme` の有無 | 結果 |
|---|---|---|
| Mermaid | 描画側の設定に従う | 追従する |
| draw.io | **無し**（色が固定値で埋め込まれる） | **追従しない** |
| 手書きSVG | 有り（自分で書ける） | 追従する |

`--svg-theme` という引数はあるが、それは書き出し時にどちらのテーマで固定するかを選ぶだけである。**1つのファイルで両方に対応することはできない。**

### 差分の読みやすさ

| 方式 | 図を1か所直したときの差分 |
|---|---|
| Mermaid | 1行。人が読める |
| draw.io | 座標を含む XML 属性が複数行。人にはほぼ読めない |
| 手書きSVG | 直した要素の行だけ。人が読める |

### 作成と編集の手間

| 方式 | 作成 | 編集 |
|---|---|---|
| Mermaid | 速い。配置は自動 | 速い |
| draw.io | 画面上で操作できるが、この環境に GUI が無い | GUI があれば最も速い |
| 手書きSVG | 遅い。座標を自分で決める | 遅い |

## 決定

**3方式を用途で使い分ける。1つに統一しない。**

| 図の種類 | 使う方式 | 理由 |
|---|---|---|
| 流れ、順序、状態遷移、構造の関係 | **Mermaid** | 正本が小さく、差分が読め、テーマに追従する。配置の自動決定で十分 |
| 概念図、比較図、標準の顔になる図 | **手書きSVG** | 配色と余白を制御でき、明暗テーマに追従し、ファイルが小さい |
| 人が画面上で描き直す前提の図 | **draw.io** | GUI で編集できることの価値が、出力サイズの欠点を上回る場合に限る |

**既定は Mermaid とする。** Mermaid で表せない、または見た目の制御が必要になったときだけ、手書きSVG に上げる。

**draw.io は既定にしない。** 出力が 42 倍になり、明暗テーマに追従せず、この環境には GUI が無い。ただし、**利用者が自分で描き直したい図のために、実行できる状態は維持する**（`tools/export_diagrams.sh`）。

## 結果と影響

### 良くなること

- サイトの図は、ほとんどが Mermaid のテキストとして Git に入る。差分が読める。
- 明暗テーマの切り替えで図が読めなくなることがない。
- 図の総量が増えてもリポジトリが膨らまない。

### 悪くなること・引き受ける負担

- 図の形式が3つになる。どれで作るかの判断が要る。上の表がその判断表である。
- 手書きSVG は作成に時間がかかる。**そのため、手書きSVG は数点に限る。**
- `.drawio` と手書き `.svg` で**同じ基底名を使うと、書き出しが互いを上書きする。** 実際に一度起きた。基底名を分ける（`quality-axes.svg` と `quality-axes-drawio.drawio`）。

### draw.io を Docker で動かすときの注意

実測で分かった3点を `tools/export_diagrams.sh` に書いてある。

1. `--user` を付けないと、書き出したファイルの所有者が root になる。
2. `--user` を付けると HOME が無くなり、**Electron が何も出力せずに終了する。** `-e HOME=/tmp` を渡す。
3. 入力にディレクトリを渡すと、draw.io が `.mmd` まで図として扱い、同名の出力を上書きする。`.drawio` を1件ずつ渡す。

## 検討したが採らなかった案

| 案 | 採らなかった理由 |
|---|---|
| すべて Mermaid | 概念図の配色と余白を制御できない。標準の顔になる図が作れない |
| すべて draw.io | 出力が 42 倍。明暗テーマに追従しない。GUI が無い環境では利点が出ない |
| すべて手書きSVG | 作成コストが高すぎる。図を足すたびに時間がかかり、結果として図が増えない |
| 画像（PNG）にする | 文字が検索できない。拡大でぼやける。明暗テーマに追従しない |
