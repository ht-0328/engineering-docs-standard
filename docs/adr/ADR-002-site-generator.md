# ADR-002 サイト生成を自作と Zensical の二本立てにして比べる

| 項目 | 内容 |
|---|---|
| 状態 | 検討中 |
| 決定日 | 次の版で決める |
| 決定者 | このリポジトリの保守担当 |
| 関連 | [ADR-001](ADR-001-diagram-tool.md)、[10-operations.md](../10-operations.md) |

**決定**: いまは一本に決めない。両方を動く状態で置き、次の版で決める。**比べるあいだは、両方を公開する。正本は `tools/build_site.py` が作った本編である。**

## 状況

この標準のサイトは、[tools/build_site.py](../../tools/build_site.py) が作っている。843行の自作である。

Markdown の解析には既存の部品を使う。**ページの組み立て、見た目、検索、リンクの書き換えは自分たちで書いている。**

2025年11月、[Zensical](https://zensical.org/) が公開された。Material for MkDocs を作った人たちによる、新しいサイト生成の道具である。

**「なぜ自作なのか」を記録していなかった。** そのため、この問いが出るたびに調べ直すことになっていた。この記録はそれを止めるために書く。

## 決定

**二本立てにする。どちらも動く状態で置く。**

| 道具 | 入口 | 公開先 | 位置づけ |
|---|---|---|---|
| 自作 | `tools/build_site.py` | `/` | **正本** |
| Zensical | `tools/build_site_zensical.py` | `/zensical/` | 比較用 |

**両方を公開する。** 見た目を比べてもらうには、URL を開くだけで見られる必要があるためである。

正本が2つあるように見えることは、この決定のいちばんの危険である。そのため、次の3つで打ち消す。

| 打ち消し方 | 置き場 |
|---|---|
| 最初のページに「これは比較用である」と大きく出す | `tools/build_site_zensical.py` の `NOTICE` |
| すべてのページの下に、本編への案内を出す | `zensical.toml` の `copyright` |
| 検索結果に出さない | `tools/build_site_zensical.py` の `add_noindex` |

検索避けに `robots.txt` は使えない。**その置き場はドメインの直下にある。** GitHub Pages のプロジェクトサイトからは、そこを触れない。そのため、ページごとに指示を入れている。

## AI向けの別冊は対象外にする

**`docs-ai/` は Zensical 版を作らない。** 比較用の試験に、二重の生成物を足す理由が無い。

| 対象 | 自作（`build_site.py`） | Zensical |
|---|---|---|
| 本編（`docs/`） | `/` | `/zensical/` |
| AI向けの別冊（`docs-ai/`） | `/ai/` | **作らない** |

決めた経緯は [ADR-003](ADR-003-ai-volume.md) にある。

## 理由

同じ `docs/`（14ページ）を両方で作って測った。測定日は 2026-08-31 である。

| 観点 | 自作 | Zensical |
|---|---|---|
| 自分たちが書く量 | 843行（CSS と JS を内包） | 326行（下ごしらえ173行、図の描画61行、設定92行） |
| 生成にかかる時間 | 約 0.8 秒 | 約 1.0 秒 |
| 出力の大きさ | 724 KB | 1.8 MB |
| 外部への通信 | 無し | 既定で書体を取りに行く。設定で止められる |
| 日本語の見出し | 見出しの語がそのままアンカーになる | 既定では `_2` `_3` になる。設定で直せる |
| 検索 | 自作の索引 | 同梱。日本語も語ごとに区切られる |
| 版の安定度 | 自分たちの責任 | 0.0.57。公開されている分類は Alpha |

出力の大きさは、どちらも Mermaid（3.5 MB）を除いた値である。時間には Docker の起動を含む。

### 分かったこと

**1. 乗り換えても、自作のコードは無くならない。**

Zensical 版でも326行は自分たちで書いている。減るのは517行である。残る理由は3つある。

| 残るもの | 理由 |
|---|---|
| リンクの書き換え | Zensical は `docs_dir` の中だけを扱う。`../README.md` のような外向きのリンクが26箇所ある |
| 図の描画 | Zensical は ```mermaid を印付きの塊にするだけで、描画する部品を同梱しない |
| 設定 | 並び順、見出しの規則、書体を読まない指定を自分で書く |

**2. 日本語は、既定のままでは壊れる。**

見出しのアンカーが `_2` `_3` のような通し番号になる。本文中の `#日本語の見出し` へのリンクが、9箇所すべて切れた。[tools/mdslug.py](../../tools/mdslug.py) の規則を渡して直した。

検索は問題なかった。日本語を語ごとに区切って索引にしている。

**公開されている説明には「検索は英語のみ」と書いてある。** 実際に生成したものを調べると、日本語も区切られていた。画面の文言も日本語になっている。

**3. 速さの利点は、この規模では出ない。**

Zensical は差分での作り直しが速いことを利点に挙げている。14ページでは、その差が Docker の起動時間に埋もれる。**ページ数が数百に増えたときに効く利点である。**

## 結果と影響

この決定で良くなることと、引き受ける負担を分けて書く。

### 良くなること

- 「なぜ自作か」に、測った数字で答えられる。
- 見た目と検索の保守を手放す道が、動く形で用意された。
- どちらを選んでも、`docs/` の Markdown は正本のままである。

### 悪くなること・引き受ける負担

- 作業用のイメージが2つになる。`edocs-tools` と `edocs-zensical` である。
- `docs/` を直したとき、両方で確かめる手間が増える。CI で両方を作って確かめる。
- 決めずに置くと、二本とも中途半端に古くなる。**次の版で決める。**

### 決める条件

次のどれかが起きたときに、あらためて判断する。

| 条件 | 判断 |
|---|---|
| Zensical が Alpha を抜ける | 乗り換えを前向きに検討する |
| ページ数が100を超える | 差分での作り直しの利点が出る。乗り換えを検討する |
| 自作の CSS と JS の直しが続く | 保守の重さが乗り換えの理由になる |
| 日本語まわりで新たな不具合が出る | 自作を続ける理由が強まる |

**どちらに決めても、比較用の公開はそこで終える。** `/zensical/` を残したまま忘れることが、いちばん起きやすい失敗である。

## 検討したが採らなかった案

| 案 | 採らなかった理由 |
|---|---|
| いますぐ Zensical に一本化する | 版が 0.0.57 で分類は Alpha である。公開が止まる危険を、いま負う理由が無い |
| Zensical を採らないと決める | 517行を手放せる可能性がある。測らずに捨てるのは早い |
| MkDocs と Material for MkDocs にする | 作った人たち自身が Zensical に軸足を移している。二度乗り換えることになる |
| 比較用は公開せず、手元と CI の成果物だけで見る | 見た目の比較を人に頼めない。落として開く手間が、比較そのものを止める |

**「両方を公開する」は、いちど採らない案に入れていた。** 理由は「読者にとって正本が2つになる」であった。断り書き、下部の案内、検索避けの3つで打ち消せると判断し、採る側に移した。
