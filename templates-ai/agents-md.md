| 項目 | 内容 |
|---|---|
| 発信日 | （例: 2026-08-31） |
| 作成者 | （例: 山田 太郎（基盤チーム）） |

| この文書を読んだあと読者ができること | （例: 道具をまたいで使える指示書を書ける） |

## この型の使い方

**下の枠の中身を `AGENTS.md` としてリポジトリの根に置く。** この説明の部分は写さない。

守る規則は [docs-ai/03-instructions.md](../docs-ai/03-instructions.md) にある。特に次の3つを守る。

| 規則 | 内容 | 根拠の強さ |
|---|---|---|
| `AN-05` | 確かめられる形で書く | Anthropic と OpenAI が一致 |
| `AN-09` | AIが既に知っていることを書かない | Anthropic の公式文書 |
| `AN-04` | 200行以内を目標にする | **下の注を読む** |

**`AN-04` の200行という数値は、`AGENTS.md` の仕様に由来しない。**

| 出典 | 長さについて何と言っているか |
|---|---|
| AGENTS.md の公式仕様 | **何も定めていない。** 「必須項目は無い。標準の Markdown である」とだけ述べる |
| Claude Code の公式文書 | `CLAUDE.md` について「200行以内を目標にする」と述べる。**測定結果は示されていない** |

つまり200行は、**別の製品の推奨を借りたものである。** それでも目安として置くのは、長い指示書ほど守られにくいという主張が複数の出典で一致しているためである（`AD-11`）。

**使う道具で違う値が示されているなら、そちらに従う。**

- 組み立て: `make build`
- 単体試験: `make test`（`tests/unit/` だけを走らせる）

**変更を提案する前に `make verify` を実行する。** これは上の4つをまとめて走らせる。

## 書いてはいけないもの

**次はすべて `AN-08` と `AN-09` に反する。**

| 書かないもの | 理由 |
|---|---|
| ディレクトリ構成の全体 | AIが自分で調べられる |
| 依存ライブラリの一覧 | 設定ファイルにある |
| （例: Go とは何か、テストとは何か） | AIが既に知っている |
| 特定のファイルを触るときだけ要る決まり | そのディレクトリに置く（`AN-03`） |
| 複数段階の作業手順 | スキルにする |

## 確かめること

- [ ] 200行以内である
- [ ] 各項目について、守ったかどうかを機械的に確かめられる
- [ ] 矛盾した記述が無い
- [ ] AIが探せば分かることを書いていない
- [ ] 必ず守らせたいことは、仕組み（権限設定や hook）で止めている
