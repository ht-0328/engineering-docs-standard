# 05 人とAIの両方が読む文書

**多くの文書は、人とAIの両方が読む。** 手順書も、設計書も、社内の知識も、いまは両方に読まれる。

規則IDは `AH-xx` を使う。

## この章が答える問い

**「AI向けに書くと、人にとって読みにくくなるのではないか。」**

答えは「**ほとんどの規則では、ならない。**」である。ただし3つだけ、はっきりぶつかる箇所がある。この章はそこを扱う。

## ほとんどの規則は両方に効く

本編（人向け）と [02章](02-ai-readable-docs.md)（AI向け）を突き合わせると、大半は同じ方向を向いている。

| 規則 | 人に効く理由 | AIに効く理由 | ぶつかるか |
|---|---|---|---|
| 用語を統一する | 読み違えを防ぐ | 見つけてもらえる | ぶつからない |
| 結論を先に書く | 走査する読者が拾う | 真ん中が読み落とされる | ぶつからない |
| 見出しを具体的にする | 内容を予測できる | 断片が何の話か分かる | ぶつからない |
| 曖昧な語を使わない | 解釈が割れない | 実行を決められる | ぶつからない |
| 廃止した記述を消す | 混乱しない | 誤って拾われない | ぶつからない |
| 時点に依存する語を使わない | 古びない | 書かれた時点が分からない | ぶつからない |

**理由は違うが、結論が同じである。** そのため、AI向けに書き直した文書は、人にとっても読みやすくなることが多い。

| ID | 規則 | 強さ | 出典 |

## ぶつかる箇所1: 繰り返し

**人向けの文章術は、繰り返しを嫌う。AI向けは、繰り返しを求める。**

人向けの規則では、同じ語を何度も書くのは稚拙とされる。だから2回目以降は「これ」「同ジョブ」と受ける。

**AI向けでは、それが致命的になる。** 節が切り分けられて渡ると、指すものが消える。

### AH-01 繰り返しを恐れない。各節で主語を書く

**必須。**

**この規則は、自分で測った結果に基づく。** 同じ事実を4通りに書き分け、切り分けて渡したときの正答率を、2つのモデルで比べた。

| 版 | 見出し | 本文 | 正答率（Gemini 系） | 正答率（GPT 系） |
|---|---|---|---|---|
| A | 具体的 | 自己完結 | **100%** | **100%** |
| C | 一般的 | 自己完結 | **100%** | **100%** |
| D | 具体的 | 前の節に依存 | 25% | 100% |
| B | 一般的 | 前の節に依存 | 0% | 50% |

**本文を自己完結させた版（AとC）だけが、両方のモデルで100%だった。** 本文が前の節に依存する版（DとB）は、モデルによって結果が大きく変わった。

**D版とB版の「高い正答率」は、理解によるものではない。** 誤った節をわざと渡す条件を足したところ、B版で GPT 系は8問中5問で、別のジョブの値を断定して答えた。**当てずっぽうが半分当たっていただけである。**

**この数値をそのまま一般化しない。** 材料は9節・約2,000文字が1件、質問は8問、統計的な検定はしていない。**言えるのは「本文の自己完結は、モデルが変わっても結果が変わらない唯一の条件だった」までである。**

詳しい手順、3つ目の条件の結果、弱点の一覧は [付録 実験の記録](appendix-experiments.md) にある。

### 人にとって読みにくくなるか

**節をまたぐ繰り返しは、人にはほとんど気にならない。** 人は節を続けて読むが、その繰り返しは1文か2文である。

気になるのは**同じ節の中の繰り返し**である。そこでは受ける語を使ってよい。

```markdown
## Haiton 夜間集計ジョブのログ保持期間

Haiton の夜間集計ジョブのログは、90日間保持する。
この期間を過ぎたログは、自動で削除される。
```

2文目の「この期間」は同じ節の中を指すので、切り分けても壊れない。

**規則は「節をまたいで指さない」であって、「指す語を使わない」ではない。**

**出典**: `SRC-AIEXT-008`（A-4）、`SRC-AIEXP-001`

## ぶつかる箇所2: 図

**人は図から情報を読み取れる。AIは、図を渡されるとは限らない。**

### AH-02 図には、同じ情報を持つ本文を必ず添える

**必須。**

本編の P-03 は代替テキストを求める。**それでは足りない。** 代替テキストは図の説明であって、図が持つ情報そのものではない。

**画像を読めるモデルは存在する。** それでも本文に書く理由は2つある。

| 理由 | 内容 |
|---|---|
| 1 | **検索して一部を渡す仕組みは、多くが本文だけを索引にする。** 図は索引に入らない |
| 2 | 図が渡っても、細部の読み取りは保証されない |

| 図の種類 | 添えるもの |
|---|---|
| 手順の流れ図 | 番号つきの手順の文章 |
| 構成図 | 構成要素と関係を並べた表 |
| 画面の写真 | 操作する場所と、表示される文言 |

**図は理解を助けるために置く。情報の正本にしない。**

### 人にとって冗長にならないか

なる場合がある。**そのときは、本文を先に置き、図を後に置く。**

人は図を見て分かれば本文を読み飛ばす。AIは本文を読む。**両立する。**

**出典**: `SRC-AIEXT-006`

## ぶつかる箇所3: 量

**人は長い文書を読み飛ばせる。AIは長い文書で精度を落とす。**

人向けの文書は、丁寧な説明や背景があるほうが親切なことが多い。AI向けでは、それが正答率を下げる。

### AH-03 読者ごとに文書を分けるかは、量で決める

**推奨。**

公開仕様 AGENTS.md は、**分けることを勧めている。** README は人のため、AGENTS.md はAIのためと明記している。

しかし、**分ければ重複が生まれ、片方が古くなる。** 本編の O-04（一つの事実の正本は一つにする）に反する。

判断の目安を置く。

| 状況 | やること |
|---|---|
| AI向けに足したい記述が、**行数で**全体の2割未満 | **分けない。** 一つの文書で両方をまかなう |
| AIへの指示（守らせたい決まり）が中心 | **分ける。** 指示書は [03章](03-instructions.md) の規則に従う |
| 人向けの背景説明が長い | **分ける。** 背景は人向けに残し、決まりだけを指示書に書く |

**この目安に出典は無い。この別冊が運用上決めたものである。** 2割は行数で数える。`wc -l` で確かめられる。

**出典**: `SRC-AIEXT-004`（分けること自体の根拠）。2割という目安は**出典なし・運用上の取り決め**

## AH-04 人向けの注記は、AIに読ませない形で書く

**任意。道具によって使えるかが違う。**

指示書の公式文書は、HTMLのコメントが読み込み前に取り除かれると書いている。

> Block-level HTML comments (`<!-- maintainer notes -->`) in CLAUDE.md files are stripped before the content is injected into Claude's context.

つまり、**保守する人へのメモを、AIのトークンを使わずに残せる。**

```markdown
<!-- この決まりは2026-08の障害を受けて足した。消す前に運用チームへ確認する -->
デプロイ前に `make verify` を実行する。
```

**この挙動は道具によって違う。** 使う道具で確かめてから使う。

**出典**: `SRC-AIEXT-007`

## 迷ったときの決め方

**両方の読者を満たせないときは、次の順で決める。**

1. **誤りが起きるほうを避ける。** 人が読みにくいだけなら直せる。AIが誤った答えを出すと、誰も気づかないまま使われる。
2. **人が確かめられる形を残す。** AI向けに最適化した結果、人が検証できなくなる書き方は選ばない。
3. **測る。** 迷いが残るなら、両方書いて測る。手順は [付録 実験の記録](appendix-experiments.md) にある。

**この順序に出典は無い。この別冊が運用上決めたものである。**
