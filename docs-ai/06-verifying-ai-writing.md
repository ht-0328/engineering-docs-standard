# 06 AIに書かせた文書の確かめ方

**AIに書かせた文書は、書けた時点では未検証である。** この章は、それを検証するための規則を置く。

規則IDは `AV-xx` を使う。

## この章の根拠は、この別冊を作った作業そのものである

**この別冊は、Claude と Codex と Antigravity(agy) の3つで作った。** その過程で、AIの出力に実際の誤りが出た。

**その誤りを、隠さずに規則の根拠として使う。** 何が起きたかは各規則に書く。生の記録は [research/external/](../research/external/) にある。

## 規則の一覧

| ID | 規則 | 強さ | 出典 |
|---|---|---|---|
| `AV-01` | 主張ごとに出典を書かせる | 必須 | `SRC-AIEXP-002` |
| `AV-02` | 数値と固有名詞は、必ず原文に当たる | 必須 | `SRC-AIEXP-002` |
| `AV-03` | 「無い」ことをAIに確認させない | 必須 | `SRC-AIEXP-002` |
| `AV-04` | 未検証であることを、文書自身に書く | 必須 | `SRC-AIEXT-003` |
| `AV-05` | 独立した別のAIに、同じことを調べさせる | 推奨 | `SRC-AIEXP-002` |
| `AV-06` | モデルによって失敗の仕方が違うと考える | 推奨 | `SRC-AIEXT-005` |
| `AV-07` | 検証した人と日付を残す | 必須 | `SRC-AIEXT-003` |

`SRC-AIEXP-002` は、この別冊を作る過程で実際に起きたことの記録である。

---

## AV-01 主張ごとに出典を書かせる

**必須。**

調べさせるときは、次を指示に入れる。

1. 主張ごとに、URLと確認日を書く。
2. **原文を引用し、その下に訳を置く。**
3. 取得できなかったものは「取得できなかった」と書く。推測で埋めない。
4. **推測した部分には印を付ける。**

**4番目が効く。** 印を付けるよう求めると、印の付いた記述が実際に出てくる。印が無ければ、推測と事実が混ざったまま渡される。

### 効果

この別冊の調査では、この指示を使った。結果として、AIの報告に「取得できなかった（404）」という記述が実際に含まれた。**書かせなければ、その部分は推測で埋められていた可能性が高い。**

**出典**: `SRC-AIEXP-002`

## AV-02 数値と固有名詞は、必ず原文に当たる

**必須。この章で最も重要な規則である。**

### 実際に起きたこと

この別冊の調査で、agy に実測研究を集めさせた。報告は詳細で、論文名・著者・arXiv番号・数値が並んでいた。

**私が原文に当たって確認したところ、次の誤りがあった。**

| 項目 | AIの報告 | 原文 |
|---|---|---|
| 論文の著者名 | Hosein Deilamsalehy | **Hanieh** Deilamsalehy |
| 論文の著者名 | Tung Bui | **Trung** Bui |
| 数値 | Recall@5 が17〜25%向上 | **要旨に数値の記載なし** |
| 数値 | Macro Accuracy が30%未満に低下 | **要旨に数値の記載なし** |

**論文そのものは実在し、中心の主張も正しかった。** 誤っていたのは、細部の転記と、原文に無い数値の付加である。

### 何が危ないか

**「だいたい合っている」報告が最も危ない。** 全部でたらめなら気づく。**論文名も主張も正しく、数値だけが違うと気づかない。**

そして数値は、そのまま規則の根拠として引用される。

### 原文に当たるときにやること

| 対象 | 確認の仕方 |
|---|---|
| 数値 | 原文に当たる。**要旨に無ければ「未確認」と書く** |
| 人名・製品名・版数 | 原文に当たる |
| 引用文 | 原文と1文字ずつ比べる |
| 主張の方向 | 要旨で足りることが多い |

**出典**: `SRC-AIEXP-002`

## AV-03 「無い」ことをAIに確認させない

**必須。**

「この仕様に◯◯の規定はあるか」と聞いて「ありません」と返ってきても、それは根拠にならない。**探せなかったことと、存在しないことは違う。**

### 実際に起きたこと

Web検索の上位に出た解説記事の複数が、「Claude Code は `CLAUDE.md` が無ければ `AGENTS.md` を読む」と書いていた。agy の調査はこれを否定した。

**公式文書に当たったところ、agy が正しかった。**

> "Claude Code reads `CLAUDE.md`, not `AGENTS.md`."

**このときは補助AIが正しく、二次情報が誤っていた。** つまり、「AIが間違える」でも「AIが正しい」でもなく、**一次情報に当たるまで決まらない**、というのが正しい理解である。

### 「無い」ことを確かめるときにやること

**「無い」ことを確かめたいときは、一次情報の該当箇所を自分で開く。** AIには「どこを見れば分かるか」を聞く。

**出典**: `SRC-AIEXP-002`

## AV-04 未検証であることを、文書自身に書く

**必須。**

AIが作った文書は、検証されるまで未検証である。**そのことを文書の冒頭に書く。**

このリポジトリの一次ノートは、すべて次の形の断り書きから始まる。

```markdown
> **この文書の出どころ**: Codex が抽出テキストを読んで作成した一次ノートである。
> **未検証の記述が含まれる可能性がある。この文書を単独の根拠として使わない。**
> 作成日: 2026-08-31
```

**「単独の根拠として使わない」まで書く。** 「参考情報です」では弱い。何をしてはいけないかを書く。

### 検証が済んだら

**断り書きを消すのではなく、検証した範囲を書き足す。**

```markdown
> 検証: 2026-08-31、`SRC-AIEXT-008` の A-1 から A-5 について原文を確認した。
> B節に挙げた数値は未確認のままである。
```

**出典**: `SRC-AIEXT-003`（時点に依存しない書き方）

## AV-05 独立した別のAIに、同じことを調べさせる

**推奨。**

同じ対象を、別の系列のAIに独立に調べさせ、突き合わせる。**食い違った箇所が、確認すべき箇所である。**

### 効果と限界

この別冊の調査では、この方法で1件の食い違いが見つかり、原文に当たって決着した（`AV-03` の例）。

**ただし、限界がある。**

| 期待できること | 期待できないこと |
|---|---|
| 一方が見落とした情報が出る | **両方が同じ誤りをすることがある** |
| 食い違いが検証すべき箇所を示す | 一致していても正しいとは限らない |

**一致は正しさの証明ではない。** 二次情報が広く誤っていれば、両方が同じ誤りをする。

**出典**: `SRC-AIEXP-002`

## AV-06 モデルによって失敗の仕方が違うと考える

**推奨。**

企業の実測レポートは、モデル系列ごとの癖を報告している。

| 系列 | 報告された癖 |
|---|---|
| Claude | 最も慎重。あいまいなときに答えを控える |
| GPT | 作り話をする率が最も高い。入力に無い語を出すことがある |
| Gemini | 500〜750語あたりから、入力に無い語を出し始める |

**この別冊の実験でも、同じ方向の結果が出た。実際に測った。**

情報が足りない節を渡し、答えられないはずの質問をした。**正しい振る舞いは「わからない」と答えることである。**

| 系列 | 8問での振る舞い |
|---|---|
| Gemini 系 | **8問すべてで「わからない」と答えた。誤答は0件** |
| GPT 系 | **3問だけ「わからない」と答えた。残る5問で、別の対象の値を断定して答えた** |

GPT 系が返した誤答である。

| 質問 | 正しい答え | 返ってきた答え |
|---|---|---|
| 夜間集計ジョブの通知先 | `ops-haiton@example.com` | **`sync-haiton@example.com`** |
| 夜間集計ジョブの件数上限 | 50000件 | **10000件** |

**通知先も上限も、別のジョブのものと入れ替わっていた。** しかも断定した答えとして返ってきた。

**同じ文書が、モデルによって違う壊れ方をした。** 慎重なモデルでは「情報が足りない」と分かる。そうでないモデルでは、**誰も気づかないまま誤った値が使われる。**

### モデルの違いを確かめるときにやること

1. **「わからない」と答えたことを、良い結果と数えない。** 情報が足りない文書であることに変わりはない。
2. **使う予定のモデルすべてで確かめる。** 慎重なモデルで通った文書が、そうでないモデルで誤答を生む。**これは推測ではなく、測って確かめたことである。**
3. **誤った節をわざと渡して試す。** 正しい節を渡す試験だけでは、この違いは見えない。

手順と生の結果は [付録 実験の記録](appendix-experiments.md) にある。

**出典**: `SRC-AIEXT-005`、`SRC-AIEXP-001`

## AV-07 検証した人と日付を残す

**必須。**

| 残すもの | 理由 |
|---|---|
| 誰が検証したか | 責任の所在 |
| いつ検証したか | 出典が変わっていないかを判断できる |
| **何を検証していないか** | ここが最も重要 |

**「検証済み」とだけ書かない。** 検証の範囲を書く。範囲が書かれていない検証は、次の人がやり直すしかない。

この別冊では、[research/external/](../research/external/) の各ノートに「裏が取れなかった数値」の節を置いている。

**出典**: `SRC-AIEXT-003`

## 検証の手順

`AV-01` から `AV-07` までの規則を、実行する順に並べる。

1. **調べさせる前に**、`AV-01` の4点を指示に入れる。
2. 別のAIにも同じことを調べさせる（`AV-05`）。
3. 報告が返ったら、**食い違った箇所を先に確認する。**
4. **すべての数値と固有名詞について、原文を開く**（`AV-02`）。
5. 確認できなかったものを、別の節に分けて「未確認」と書く。
6. 文書の冒頭に、検証の範囲と日付を書く（`AV-04`、`AV-07`）。

**4番を飛ばすと、この手順は意味を失う。**
