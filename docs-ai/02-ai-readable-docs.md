# 02 AIが読む文書の規則

**この章の規則は、AIが検索して読む文書に当てはめる。** 手順書、仕様書、設計書、社内の知識など、人もAIも参照する文書が対象である。

規則IDは `AD-xx` を使う。根拠は [01 AIはどう読むか](01-how-ai-reads.md) にある。

## 規範の強さ

本編と同じ3段階を使う。

| 強さ | 意味 |
|---|---|
| **必須** | 守らないと、**誤った答えや取りこぼしが起きる危険が大きく増える。** この標準では守る |
| **推奨** | 守ると精度が上がる。守らなくても致命的ではない |
| **任意** | 場合による |

**「必須」は必然ではない。** 出典が示しているのは、多くの場合に成績が落ちるという傾向である。**守らなければ必ず失敗する、とは言えない。**

## AD-01 節は、それだけで意味が通るようにする

**必須。**

文書は切り分けられて渡される。**節が単独で渡ることがある。** 前後がまとめて渡る仕組みもあるが、**それを当てにできない。** その節だけを読んで意味が通らなければ、そこに書いた事実は使えない。

判定は簡単である。**その節だけを切り取って人に見せ、答えられるかを見る。**

### 何を節の中で完結させるか

| 完結させるもの | 理由 |
|---|---|
| 主語（何についての話か） | 前の節に書いても渡らない |
| 前提条件 | 「上で述べた条件のもとで」は成り立たない |
| 固有名詞 | 略称だけでは、どの製品か決まらない |

### 悪い例と直し方

悪い例。前の節に主語がある。

```markdown
## 保持

上記のジョブが出力するものは、90日間保持される。
```

良い例。節の中で主語が決まる。

```markdown
## Haiton 夜間集計ジョブのログ保持期間

Haiton の夜間集計ジョブのログは、90日間保持する。
```

### 実測した結果

**この規則は、自分で測った。** 同じ事実を4通りに書き分け、切り分けて渡したときの正答率を、2つの道具で比べた。質問は8問、呼び出しは計288回である。

| 本文 | 見出し | 正答率（Gemini 系） | 正答率（GPT 系） |
|---|---|---|---|
| **自己完結** | 具体的 | **100%** | **100%** |
| **自己完結** | 一般的 | **100%** | **100%** |
| 前の節に依存 | 具体的 | 25% | 100% |
| 前の節に依存 | 一般的 | 0% | 50% |

**本文を自己完結させた版だけが、両方の道具で100%だった。**

さらに、**誤った節をわざと渡す条件**では、本文が依存している版で GPT 系が8問中5問、別の対象の値を断定して答えた。

**この数値をそのまま一般化しない。** 材料は9節・約2,000文字が1件、統計的な検定はしていない。手順と弱点の一覧は [付録 実験の記録](appendix-experiments.md) にある。

**出典**: `SRC-AI-001`（6.3「モジュール性」。挿入・削除できる部品として書く）、`SRC-AI-003`（3.2.2「一貫性のあるテキストチャンク」）、`SRC-AIEXT-008`（A-4。EMNLP 2024。自己完結した単位が最もよく見つかる）、`SRC-AIEXT-006`、`SRC-AIEXP-001`（自分の実測）

## AD-02 見出しに、何についての話かを入れる

**必須。**

見出しは切り分けの目印であり、同時に**その断片が何の話かを示す唯一の手がかり**になることが多い。

「概要」「設定」「注意」のような見出しは、断片になった瞬間に何の情報も持たない。

### 見出しに入れるもの

- 製品名またはシステム名。
- 機能名。
- その節が答える問い。

```markdown
## Haiton 夜間集計ジョブのログ保持期間
```

この見出しは、製品名（Haiton）、機能名（夜間集計ジョブ）、問い（ログ保持期間）の3つを含む。

**出典**: `SRC-AIEXT-006`、`SRC-AIEXT-003`、`SRC-AIEXP-001`

## AD-03 前の節を指す語を使わない

**必須。** `AD-01` を、指す語の使い方として具体化した規則である。

次の語は、節をまたいで使わない。

| 使わない語 | 代わりに書くもの |
|---|---|
| これ、それ、この、その | 指すものの名前 |
| 上記の、前述の、先ほどの | その事実そのもの |
| 同様に、同じく | 同じ内容を書く |
| 後述する、下記のとおり | **実行に要る事実はその節に書く。** リンクは詳しい説明への補足だけに使う |

**節の中でなら使ってよい。** 切り分けの単位は節だからである。

**出典**: `SRC-AI-001`（6.5.3「必須条件」。前提が渡らないと成り立たない）、`SRC-AIEXT-008`（A-4）、`SRC-AIEXP-001`

## AD-04 節の答えを、節の先頭に置く

**必須。**

査読つきの研究は、答えが文脈の真ん中にあるとき、成績が大きく落ちることを示している。

本編の C-01（結論先出し）と同じ形になるが、**適用の単位が違う。** 本編は文書の先頭に結論を置く。この規則は**すべての節の先頭**に、その節の答えを置く。

```markdown
## Haiton 夜間集計ジョブを再実行できる条件

Haiton の夜間集計ジョブは、状態が `FAILED` のときだけ再実行してよい。

理由は、`RUNNING` のときに再実行すると二重に動くためである。
```

答え（`FAILED` のときだけ）が先にあり、理由が後にある。

**出典**: `SRC-AI-001`（6.1「無関心の谷」とサンドイッチ手法）、`SRC-AIEXT-008`（A-1。TACL 2024）、`SRC-AIEXT-007`

## AD-05 用語を統一し、読み手が使う語で書く

**必須。**

**この規則は、AI向けでは本編より強い。** 人向けは読み違えを防ぐための規則である。AI向けは、**見つけてもらうための**規則である。

査読つきの研究は、語句がそのまま一致する手がかりを消すと、32,000トークンで13モデル中11モデルが基準の半分を下回ることを示している。

### やること

1. 一つの概念に一つの語を決める。
2. **利用者が実際に使う語を選ぶ。** 社内の正式名称より、検索窓に打ち込まれる語を優先する。
3. 別名がある場合は、**同じ節の中に一度だけ併記する。**

```markdown
## 配送管理システム Haiton（社内での通称は「はいとん」）の再実行条件
```

### やらないこと

**表現を豊かにするための言い換えをしない。** 「ジョブ」「処理」「タスク」「バッチ」を混ぜて書くと、**どの語で探しても、その語で書いた箇所しか当たらない。** 同じ事柄を書いた他の箇所が漏れる。

**出典**: `SRC-AI-002`（4.1.1「混同されない説明を書く」）、`SRC-AIEXT-008`（A-2）、`SRC-AIEXT-005`、`SRC-AIEXT-003`

## AD-06 廃止した記述を、生きている記述の近くに置かない

**必須。**

**「近く」とは、同じ節の中、または切り分けたときに同じ断片へ入りうる範囲を指す。** 見出しで区切られていれば別である。

査読つきの研究は、関係のない記述を混ぜると成績が劇的に下がることを示している。企業の実測レポートは、**誤答の中身が、混ぜたまぎらわしい記述そのものであることが多い**と報告している。

**人は「これは古い版の話だ」と判断できることが多い。AIは拾ってしまう危険がある。**

### 扱い方

| 状況 | やること |
|---|---|
| 廃止した手順 | **版管理に履歴が残ることを確かめてから消す。** 履歴が無ければ、廃止資料の置き場へ移す |
| 残す必要がある | 別のファイルに移す |
| 同じ文書に残さざるを得ない | 末尾にまとめ、見出しで廃止と明示する |

**折りたたんだ節に退避させる手法は、この規則には使わない。** 公式のスキル文書はその形を勧めているが、それは常に全体が読まれる指示書やスキル（[03章](03-instructions.md)、[04章](04-skills-and-agents.md)）を前提とする。

**検索して一部だけが渡る文書では、折りたたんでも同じファイルの中にある。** 切り分けられれば、古い記述もそのまま渡りうる。

**出典**: `SRC-AI-002`（4.1.1。似た説明は「混乱と性能低下を招く」）、`SRC-AIEXT-008`（A-3。ICML 2023）、`SRC-AIEXT-005`、`SRC-AIEXT-009`、`SRC-AIEXP-001`

## AD-07 誤りの文言を、そのまま本文に書く

**推奨。**

利用者は、画面に出た文言をそのまま貼って質問する。**その文言が文書に無ければ、語がそのまま一致する手がかりを失う。** 見つかりにくくなる。

```markdown
## Haiton 夜間集計ジョブが `E-4012 batch size exceeded` で失敗したときの対処

`E-4012 batch size exceeded` は、処理件数が 50000件 を超えたときに出る。
```

要約した説明（「件数超過のエラー」）ではなく、**出力される文字列そのもの**を書く。

**出典**: `SRC-AIEXT-006`、`SRC-AIEXT-008`（A-2）

## AD-08 セルどうしの関係に意味がある表を使わない

**推奨。**

**判定はこうする。各行を「列名: 値」の並びに書き換えて、意味が保たれるか。** 保たれれば使ってよい。

```text
| ジョブ | 保持日数 |     →  ジョブ: 夜間集計, 保持日数: 90
| 夜間集計 | 90 |            意味が保たれる。使ってよい
```

保たれない表は、行と列の交差そのものに意味を持たせている。**切り分けや変換で崩れる。**

| 使ってよい表 | 避ける表 |
|---|---|
| 1行が1つの事実を表す | 行と列の組み合わせで意味が決まる |
| セルが短い値である | セルに複数の文が入る |
| 見出し行だけで列の意味が決まる | 前の行を見ないと読めない |

崩れる表を書きたくなったら、箇条書きか、節に分けた文章にする。

**出典**: `SRC-AIEXT-006`

## AD-09 図だけに情報を持たせない

**必須。**

本編の P-03 は、画像に代替テキストを付けることを求める。**この規則はそれより強い。**

代替テキストは図の説明である。**処理系によっては、代替テキストも図も渡らない。** 手順を図で示したなら、**同じ手順を番号つきの文章でも書く。**

図は理解を助けるために置く。**情報の正本にはしない。**

**出典**: `SRC-AIEXT-006`

## AD-10 時点に依存する語を使わない

**必須。**

本編の O-03 と同じ規則である。**AI向けではさらに強く効く。** AIは書かれた時点を知らないまま、その記述を事実として使う。

<!-- doclint-disable timeless -->

| 使わない語 | 代わりに書くもの |
|---|---|
| 現在は、今のところ | 版数と日付 |
| 今後、将来的に | 決まっている日付。決まっていないなら書かない |
| 最新の | 版数 |
| 従来の、以前は | いつからいつまでか |

<!-- doclint-enable -->

公式のスキル文書も同じことを求めている。

**出典**: `SRC-AIEXT-003`

## AD-11 一つの文書を短く保ち、分ける

**推奨。**

**「短く」に一律の行数は決めない。** 分けるかどうかは下の表で判断する。**どれも文書を見て確かめられる。**

**長さは3か所で効く。混ぜて考えない。**

| どこの長さか | 何に効くか |
|---|---|
| 検索の対象になる文書群の全体 | **検索の精度。** 似た記述が増え、取り違えやすくなる |
| 1つの節の長さ | **渡したあとの正答率。** 節が長いほど、その中で読み落とされる |
| AIに渡す量の合計 | **渡したあとの正答率。** 複数の節が渡る場合はここが効く |

`AD-01` が言う「1つの節が渡ることがある」と、この規則は矛盾しない。**効く場所が違う。**

ただし、**分ければ良いわけではない。** 分けた結果、各節が自己完結しなくなれば `AD-01` に反する。

| 判断 | やること |
|---|---|
| 一つの主題に複数の話題が入っている | 分ける |
| 分けると前提が渡らなくなる | 分けず、各節に前提を書く |
| 参照されるのは一部だけである | よく使う部分を独立させる |

**出典**: `SRC-AI-001`（6.1。簡潔さの理由は効果・費用・速度の3つ）、`SRC-AI-003`（3.2.2）、`SRC-AIEXT-001`、`SRC-AIEXT-005`、`SRC-AIEXT-008`（A-2）、`SRC-AIEXT-009`

## AD-12 AI向けの入口を一か所に置く

**任意。**

公開している文書群には、AI向けの案内を一か所に置く方法が提案されている。`llms.txt` という名前で、サイトの根に Markdown のファイルを置く。

**これは個人の提案であり、標準化団体の承認は受けていない。** 効果を測った結果も示されていない。**そのため任意にしている。**

考え方には見るべきところがある。特に「**飛ばしてよい部分を、書き手が先に指定する**」という発想は、人向けの文書には無い。

**出典**: `SRC-AIEXT-001`

## この章の規則が本編を強めている箇所

| 本編の規則 | この章 | どちらを取るか |
|---|---|---|
| C-01 文書の先頭に結論を書く | `AD-04` すべての節の先頭に答えを書く | **両方。** `AD-04` のほうが細かい |
| P-03 画像に代替テキストを付ける | `AD-09` 本文にも同じ情報を書く | **`AD-09`。** 代替テキストだけでは足りない |
| S-10 用語を統一する | `AD-05` 読み手が使う語を選ぶ | **`AD-05`。** 統一先の選び方まで決める |

**食い違いではなく、強化である。** AI向けの規則を守れば、本編の規則も満たす。
