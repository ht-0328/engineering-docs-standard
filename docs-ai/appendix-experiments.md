# 付録 実験の記録

**この別冊の規則のうち、いくつかは自分で測った。** この付録は、その手順と結果を記録する。

**うまくいかなかったことと、測れなかったことも書く。**

## なぜ測ったか

AIの分野は、書き方についての意見が大量にある。**そのほとんどは意見であって、測定ではない。**

この別冊の出典のうち、実測に基づくのは査読つき研究4件と企業の実測レポート1件だけである。**そのすべてが英語で測られている。** **この別冊で確認した範囲には、日本語で測ったものが無かった。** 体系的な文献検索はしていないため、「存在しない」とまでは言えない。

そこで測った。

## 実験1 節の自己完結が、AIの正答率を変えるか

`SRC-AIEXP-001` として、この別冊の出典に加えている。

### 何を測ったか

同じ事実を4通りに書き分け、**切り分けて渡したときに正しく答えられるか**を測った。

2つの要因を組み合わせている。

| 版 | 見出し | 本文 |
|---|---|---|
| A | 具体的（製品名と機能名を含む） | 自己完結（各文が主語を持つ） |
| B | 一般的（「条件」「保持」「連絡」「上限」） | 前の節に依存（「これ」「前者」「後者」） |
| C | 一般的 | 自己完結 |
| D | 具体的 | 前の節に依存 |

**4版が持つ事実はまったく同じである。** 書き方だけが違う。

材料は [research/experiments/exp1-self-contained/fixtures/](../research/experiments/exp1-self-contained/fixtures/) にある。

### 材料の設計

架空の配送管理システム「Haiton」の運用手引きである。**似ているが違う2つのジョブ**を置いた。

| ジョブ | 再実行 | ログ保持 | 通知先 | 件数上限 |
|---|---|---|---|---|
| 夜間集計ジョブ | 最大3回 | 90日 | `ops-haiton@example.com` | 50000件 |
| 日中同期ジョブ | 最大5回 | 30日 | `sync-haiton@example.com` | 10000件 |

**2つ置いたのは、まぎらわしい記述の影響を同時に測るためである。** 1つしか無ければ、当てずっぽうでも当たってしまう。

### 手順

1. 文書を `##` の見出しで節に分ける。
2. **決まった手続きで**節を1つ選ぶ（文字2つ組の重なりが最大のもの）。**モデルを使わないため、何度実行しても同じ節が選ばれる。**
3. その節だけを渡し、質問する。「文章から確実に決められない場合は、わからないとだけ書け」と指示する。
4. 答えを文字列の一致だけで判定する。**判定にモデルを使わない。**

3つの条件で測った。

| 条件 | 渡す節 | 何が分かるか |
|---|---|---|
| `retrieved` | 検索が返した節 | 検索と解答を合わせた結果 |
| `oracle` | 答えのある節（必ず正しい節） | **解答だけの結果** |
| `mismatch` | **もう一方のジョブの節** | **検索が外したときに何が起きるか** |

`mismatch` では、**「わからない」と答えるのが正しい。** 値を答えたら、渡していない事実を作ったことになる。

| 試行回数 | agy は各2回、codex は各1回 |
| 質問数 | 8問 |
| 呼び出し総数 | agy 192回、codex 96回 |

**下の結果は、最後の実行のものである。** それ以前に、条件を足しながら4回実行している。**途中の実行結果も消さずに [research/experiments/results/](../research/experiments/results/) に残してある。**

| 実行 | 版の数 | 条件 | 呼び出し |

### 結果3 誤った節を渡した場合

**安全の面では、この条件を特に見る。** 正しい振る舞いは「わからない」と答えることである。

| 版 | agy | codex |
|---|---|---|
| A | 16/16 正しく棄権 | 8/8 正しく棄権 |
| B | 16/16 正しく棄権 | **3/8 だけ棄権。5/8 で別のジョブの値を答えた** |
| C | 16/16 正しく棄権 | 8/8 正しく棄権 |
| D | 16/16 正しく棄権 | 8/8 正しく棄権 |

B版で codex が実際に返した答えである。

| 質問 | 正しい答え | 返ってきた答え |
|---|---|---|
| 日中同期ジョブの再実行は最大何回か | 5 | **3回** |
| 夜間集計ジョブの通知先は | `ops-haiton@example.com` | **`sync-haiton@example.com`** |

### 5番目について

**同じ文書が、モデルによって違う壊れ方をした。**

| 使った道具 | 情報が足りない文書での振る舞い |
|---|---|
| agy（Gemini 系） | **答えを控えた。** 上の表のとおり、全192回で「それ以外」は0件 |
| codex（GPT 系） | **答えた。** B版で誤った節を渡すと8問中5問。**`mismatch` 条件全体では 5/32** |

**これはモデル系列そのものの性質だとは言えない。** 使ったのは各社のコマンド行の道具であり、道具が内部で足している指示の違いが効いている可能性がある。

**B版の `oracle` で codex が示した50%を、正しく根拠づけた結果とは判断できない。** 同じ版の `mismatch` で、**渡された別ジョブの値をそのまま答えた**（8問中5問）。

**「当てずっぽう」とまでは言えない。** 渡された節の値を、質問の対象に誤って結び付けた（誤帰属）とも読める。**どちらであるかは、この実験では区別できない。**

**「うちのAIでは動いている」は、文書が正しい証拠にならない。** 一方の道具で「わからない」と言われた文書が、もう一方では断定した誤答になった。

これは `SRC-AIEXT-005`（Chroma の実測）が報告したモデル系列ごとの癖と、方向が一致する。

### この実験の弱点

**正直に書く。**

| 弱点 | 内容 |
|---|---|
| **材料が人工的である** | B版は、指す語が解けないよう意図して書いた。実際の文書がここまで壊れていることは少ない |
| **効果の大きさは材料次第である** | 「100%対0%」という差は、この材料の性質である。**一般にこの差が出るとは言えない** |
| 文書が小さい | 9節、2000文字程度である。長い文書では別の効果が出うる |
| モデルの版を記録していない | コマンド行の既定を使った。同じ結果を再現するには版の固定が要る |
| 検索の方法が単純である | 文字2つ組の重なりで測った。実際の検索は埋め込みを使うことが多い |
| 質問が8問しかない | 統計的な検定はしていない |
| **温度と乱数の種を固定していない** | `temperature` や種の値を指定も記録もしていない。**特に codex は各1回しか試していないため、偶然のばらつきである可能性を排除できない** |
| **試行回数がモデル間で揃っていない** | agy は各2回、codex は各1回である。**公平な比較になっていない** |
| **API を直接呼んでいない** | 各社のコマンド行の道具を通している。道具が内部で足している指示の違いが、挙動の差を生んだ可能性がある |
| **課題が1種類しかない** | 設定値を1つ取り出す課題だけである。**推論、要約、複数の節をまたぐ課題では測っていない** |
| **独立した材料は1件だけである** | 8問は1つの文書の中の「2ジョブ × 4項目」であり、独立した8材料ではない。**試行の繰り返しも独立した材料ではない** |
| **2つのコマンド行の道具にしか当てはまらない** | 道具の母集団に一般化できない。**モデルそのものの性質とも言えない** |
| **途中で設計を変えた探索的な実験である** | 3回目の結果を見て `mismatch` 条件を足した。**確認のための実験ではない。条件を固定した新しい材料での追試が要る** |
| **判定が文字列の一致だけである** | `50000` と `50,000` のような表記の違いを吸収するのはカンマの除去だけである。**意味が同じ別の書き方を誤って不正解にした可能性がある** |

**言えるのは「この書き方の違いは、実際に結果を変えうる」までである。** 「何%変わる」とは言えない。
